KiHan 角色配置参考

这份文档讲清楚一个角色的四个配置文件里每个字段是什么意思、什么时候生效、和谁有冲突。每个字段都附了可以直接抄的示例。

一个角色的所有配置都放在 Assets/AssetPackages/Resources/Characters/<角色目录>/ 下，由 CharacterFactory 按角色 ID 加载：

文件必需内容缺失时
actions.json是动作库：每个动作播什么动画、什么时候能被打断、攻击判定、位移、事件报错 找不到动作配置，动作库为空
*.asset是动画（AnimationFrameData），资源名就是 animKey动作播不出画面
skills.json否技能：CD、多段、查克拉、按键图标没有技能，查克拉上限 4
spawns.json否生成物：投射物、分身没有生成物
buffs.json否Buff：持续时间与循环特效没有 Buff

角色 ID 与目录的对应关系写死在 CharacterFactory.ResourceDirs 里（目前只有 90001 → Characters/naruto），新角色要在那里加一行。

通用约定

写法含义示例
字符串数值所有定点数都写成带引号的字符串，运行时用整数运算解析为定点数，保证不同 CPU 结果一致。留空或省略等于 0。只接受 [+|-]数字[.数字]，写 "3s"、"1e3" 会在加载时抛异常。"hitStun": "0.6"
秒 → 逻辑帧逻辑固定 30 帧/秒。秒数换算为 ceil(秒 × 30)，不足一帧按一帧算；0 或负数为 0。"0.2" → 6 帧
帧区间{ "x": 起, "y": 止 }，动画帧从 0 开始，两端都包含。{ "x": 7, "y": 10 } 是第 7、8、9、10 帧
像素与逻辑单位判定盒、锚点、偏移用像素；位移、速度用逻辑单位。100 像素 = 1 逻辑单位。"moveX": "0.6" = 60 像素
坐标轴x 横向（正方向 = 角色面朝方向，朝左时自动镜像），y 纵深，z 高度。
枚举字符串大多数枚举（霸体等级、事件类型、生成物类型）不区分大小写，写错静默回落默认值。例外：缓动名 tweenMethod 区分大小写；按键名写错会报错。"level": "skill" 与 "Skill" 等价
注释Unity 的 JsonUtility 不支持 // 注释。仓库根目录的 example.json、*_example.json 带注释，只能参考，不能直接放进 Resources。

帧、tick 与区间

理解所有"第几帧生效"的问题，只需要记住下面三件事。

1. 一个 tick 处理一帧动画

逻辑帧（tick）固定 30 帧/秒，动画素材也是 30 帧/秒，所以每个 tick 推进并"处理"恰好一帧动画。动画由若干步（Step）组成，每步可以持续多帧，动作总帧数 = 各步 Duration 之和。配置里所有帧号都是指这个展开后的动画帧序号，从 0 开始。

tick: 1 2 3 4 5 6 处理的动画帧: 0 1 2 3 4 5 （第 k 个 tick 处理第 k-1 帧）

2. 区间是闭区间，"处理到其中任意一帧"就成立

取消窗口、攻击段、输入接受率等区间 [x, y]：本 tick 处理的帧落在区间内即成立。动画播完后如果没有切走，会停在最后一帧（stall），此时按最后一帧判断，所以覆盖最后一帧的取消窗口会一直开着。

3. 切换在 tick 末尾统一发生，下一 tick 才播新动作

一个 tick 里所有"想切换"的请求（按键取消、播完、落地、命中……）都只是预约，等物理和命中全部结算完，再按优先级选出一个执行。新动作的起始帧在下一个 tick 才被处理。

例：attack1 的取消窗口 frameRange {x:18, y:21}，玩家一直按住攻击 tick 19：处理第 18 帧 → 窗口成立 → 预约 attack2 → tick 末尾切换 tick 20：处理 attack2 的第 0 帧
记忆口诀"处理完第 x 帧才能切"，所以窗口起点 x 的画面一定会被看到。

取消系统：cancelTag 与 beCancelledTag

这是整个动作框架最核心的设计：能不能从 A 切到 B，由 A 和 B 各说一半。

  • B 的 cancelTag：B 声明"我属于哪些标签"。比如所有技能都挂 skill 标签。
  • A 的 beCancelledTag：A 声明"在第 x~y 帧，允许哪些标签打断我"。
  • 两者有交集，且 B 的 commands 本帧满足，B 就会被预约。
{
  "id": "attack1",
  "beCancelledTag": [
    { "frameRange": { "x": 18, "y": 21 }, "cancelTag": ["move", "attack2", "skill"], "priority": 0 }
  ]
},
{
  "id": "skill1",
  "cancelTag": [ { "tag": "skill", "startFormFrame": 0, "priority": 20 } ],
  "commands":  [ { "press": ["Skill1"], "validInSec": "0.2" } ]
}

读法：attack1 的第 18~21 帧，允许带 move、attack2、skill 标签的动作打断；skill1 带 skill 标签，按下 Skill1 就能在这个窗口里切进去。

为什么要用标签而不是直接写动作 id？因为一个窗口通常要放行一大类动作。新增第 5 个技能时，只要给它挂上 skill 标签，所有已经放行 skill 的窗口自动生效，不用逐个修改。

还有一种临时窗口 tempBeCancelledTag：平时关闭，攻击命中时才打开，用来做"打中了才能取消后摇"。它只在当前动作里有效，切动作即失效。

优先级裁决

同一个 tick 里可能同时有多个预约（比如刚好落地、又被打中、又按了技能）。框架收集全部预约，选数值最大的；数值相同时先加入的赢。

受击中按替身（breakHurt）200 + 动作 priority0
被命中 → 受击动作100 + 受击动作 priority0

受击流程推进（toair→inair→fall、起身、僵直结束回 idle）90 + 目标 priority0

autoNext 是"兜底"只有在本 tick 此前没有任何预约时才会加入。只要有按键取消、受击等预约，autoNext 就不会出现。

一个逻辑帧里发生了什么

BattleWorld.Tick 的顺序（所有角色按 EntityId 从小到大依次处理）：

  1. 输入：玩家读取本帧输入；分身由大脑脚本生成输入。
  2. 动作推进，对每个角色：
    1. 无敌计时、技能 CD 与接段计时、生成物寿命、Buff 计时、僵直倒数
    2. 动画推进一帧 → 计算攻击段/受击段 → 霸体 → 移动接受率与转向 → RootMotion → 触发本帧事件
    3. 扫描所有动作，看能否主动取消 → 都没有时预约 autoNext
    4. 受击流程推进
  3. 物理：位移、跳跃、重力、落地（触发 onLand 预约）；然后抓取跟随、吸附。
  4. 命中检测：只收集，不生效。
  5. 命中结算：扣血、查克拉、受击反应、命中切换预约。
  6. 裁决：每个角色选出优先级最高的预约，真正切换动作。
  7. 生成与回收：回收结束的生成物，执行本帧的生成请求。
这个顺序带来的保证同一 tick 内"刚好落地又刚好命中"，两个结果都会先记下来再统一裁决，不会因为谁先算而不同；联机双端结果一致。

教程 1：最小可运行角色

目标：角色能站着、能走、能被打。一个能进战斗的角色至少需要下面这些动作。

{
  "data": [
    {
      "id": "idle", "animKey": "Idle", "catalog": "Base",
      "keepPlayingAnim": true,
      "autoNextActionId": "idle",
      "beCancelledTag": [
        { "frameRange": { "x": 0, "y": 999 }, "cancelTag": ["move", "attack1", "skill"], "priority": 0 }
      ],
      "inputAcceptance": [ { "range": { "x": 0, "y": 999 }, "rateX": "0", "rateY": "0", "turn": true } ]
    },
    {
      "id": "move", "animKey": "Run", "catalog": "Base",
      "keepPlayingAnim": true, "autoTerminate": true, "autoNextActionId": "idle",
      "cancelTag": [ { "tag": "move", "startFormFrame": 0, "priority": 0 } ],
      "beCancelledTag": [
        { "frameRange": { "x": 0, "y": 999 }, "cancelTag": ["move", "attack1", "skill"], "priority": 0 }
      ],
      "commands": [ { "hold": ["Move"] } ],
      "inputAcceptance": [ { "range": { "x": 0, "y": 999 }, "rateX": "1", "rateY": "1", "turn": true } ]
    },
    { "id": "hurt_1",     "animKey": "Hurt_1",     "catalog": "Hurt" },
    { "id": "hurt_2",     "animKey": "Hurt_2",     "catalog": "Hurt" },
    { "id": "hurt_toair", "animKey": "Hurt_toair", "catalog": "Hurt" },
    { "id": "hurt_inair", "animKey": "Hurt_inair", "catalog": "Hurt" },
    { "id": "hurt_fall",  "animKey": "Hurt_fall",  "catalog": "Hurt" },
    { "id": "lie",        "animKey": "Hurt_land",  "catalog": "Hurt" },
    { "id": "standup",    "animKey": "Land",       "catalog": "Hurt" }
  ]
}

逐段解释

  • idle 必须叫 idle：它是默认动作，受击结束、生成物初始化都会回到它。
  • idle 的窗口 0~999：整段动画都允许 move、attack1、skill 打断。999 只是"足够大"，超出动画长度没关系，播完停在末帧时按末帧判断，窗口仍然开着。
  • keepPlayingAnim + autoNextActionId 指向自己：播完不重新"进入" idle，只把动画从头再播，不会清掉按键缓冲。
  • move 的 hold: ["Move"]：推着摇杆就满足。move 自己的窗口也放行 move 标签，所以推摇杆期间每帧都在"取消进自己"，从而保持住。
  • autoTerminate：松开摇杆的那一帧，没有任何取消预约，autoNext 立刻把角色送回 idle，不用等跑步动画播完。
  • inputAcceptance：idle 的 rateX/rateY = 0 表示站着时推摇杆不会移动，但 turn: true 允许转身；move 的 1 表示全速移动。
  • 7 个受击动作的 id 是框架写死的，缺一个就会报错。它们只提供动画，流程由框架驱动。

教程 2：普攻连段

目标：按住攻击键自动打出 1→2 段，点一下只出一段，第 2 段允许预输入。

{
  "id": "attack1", "animKey": "Attack_1", "catalog": "Attack", "priority": 10,
  "autoNextActionId": "idle",
  "cancelTag": [ { "tag": "attack1", "startFormFrame": 0, "priority": 10 } ],
  "beCancelledTag": [
    { "frameRange": { "x": 18, "y": 21 }, "cancelTag": ["move", "attack2", "skill"], "priority": 0 }
  ],
  "commands": [
    { "press": ["Attack"], "validInSec": "0.2" },
    { "hold": ["Attack"] }
  ],
  "attackPhase": [ { "frameRanges": [{ "x": 7, "y": 10 }], "tag": [], "attackPhase": 0, "priority": 10 } ],
  "rootMotion":  [ { "frameRange": { "x": 8, "y": 10 }, "moveX": "0.6" } ],
  "attacks": [
    { "attack": "50", "hitStun": "0.6",
      "push": { "x": "0.6", "inSec": "0.15", "tweenMethod": "Slowly" },
      "canHitSameTarget": 1 }
  ]
},
{
  "id": "attack2", "animKey": "Attack_2", "catalog": "Attack", "priority": 10,
  "autoNextActionId": "idle",
  "cancelTag": [ { "tag": "attack2", "startFormFrame": 0, "priority": 10 } ],
  "commands": [
    { "press": ["Attack"], "validInSec": "0.3" },
    { "hold": ["Attack"] }
  ]
}

为什么 commands 要写两条

commands 里任意一条满足即可：

  • press 是"按下"事件，带 0.2 秒缓冲。在窗口打开前提前点一下，等窗口打开时仍然有效，这就是预输入。
  • hold 是"正按着"。一直按住攻击键，窗口一开就接下一段，这就是长按连段。
按下会在切动作时被用掉从 idle 按攻击进入 attack1 的那一刻，这次"按下"就被消费了。所以只配 press 时，按住不放不会连段，必须松开再按。这是有意的设计，防止一次按键打出两段。

攻击是怎么接上判定的

  • attackPhase 决定哪几帧开攻击盒：第 7~10 帧，使用 attacks[0] 的数值。
  • 攻击盒的形状在帧库（CharacterSpriteLibrary）里逐帧画，配置里不写。
  • canHitSameTarget: 1：这个动作里同一个目标最多打一次。

教程 3：单段技能与 CD

技能分两半：动作写在 actions.json（怎么放），规则写在 skills.json（CD、查克拉）。

// actions.json
{
  "id": "skill1", "animKey": "Skill_A_1", "catalog": "Skill", "priority": 20,
  "autoNextActionId": "idle",
  "cancelTag": [ { "tag": "skill", "startFormFrame": 0, "priority": 20 } ],
  "commands":  [ { "press": ["Skill1"], "validInSec": "0.2" }, { "hold": ["Skill1"] } ],
  "armorPhase": [ { "range": { "x": 0, "y": 29 }, "level": "Skill" } ],
  "beCancelledTag": [ { "frameRange": { "x": 30, "y": 33 }, "cancelTag": ["move", "attack1"], "priority": 0 } ]
}

// skills.json
{
  "chakraMax": 4,
  "data": [
    { "id": "skill1", "button": "Skill1", "cooldown": "3",
      "icon": "UI/SkillButton/90001_SkillIconAtlas#90001_SkillIconAtlas_0",
      "stages": [ { "actionId": "skill1" } ] }
  ]
}
  • 出招由动作的 commands 决定，不是 button。button 只决定 CD 遮罩显示在哪个按钮上。
  • CD 什么时候开始：离开技能的那一帧（进入 idle 时），不是按下时。释放过程中 CD 为 0。
  • CD 期间按键仍然会被检测，但技能准入拒绝，所以什么都不会发生。
  • 霸体 Skill：第 0~29 帧被普通攻击打中只扣血、不会被打断；对方攻击的 armorBreak 达到 Skill 才能打断。

教程 4：命中派生（变体动作法）

需求：鸣人技能 2 的第一段是起跳攻击。打中了，落地后接第二段；没打中，落地硬直后回 idle。

难点在于"打中过"这个信息要跨两个动作（空中段 → 落地段）才能用上，而框架没有可查询的"命中过"状态。解决方法是把分支编码进动作本身：命中时切到一个"命中版"的同动画动作，后面的流程都走命中版。

skill2_1─ 落地 / 播完 →skill2_land→idle
命中（keepFrame）↓
skill2_1_hit─ 落地 / 播完 →skill2_land_hit─ 播完 →skill2_2→idle 
{
  "id": "skill2_1", "animKey": "Skill_B_1", "catalog": "Skill", "priority": 20,
  "autoNextActionId": "skill2_land",
  "onLand": { "changeType": 1, "param": "skill2_land", "priority": 100 },
  "cancelTag": [ { "tag": "skill", "startFormFrame": 0, "priority": 20 } ],
  "commands":  [ { "press": ["Skill2"], "validInSec": "0.2" }, { "hold": ["Skill2"] } ],
  "rootMotion": [ { "frameRange": { "x": 9, "y": 9 }, "velocityX": "8", "velocityZ": "5" } ],
  "attackPhase": [ { "frameRanges": [{ "x": 19, "y": 26 }], "tag": [], "attackPhase": 0, "priority": 10 } ],
  "attacks": [
    { "attack": "100", "hitStun": "0.8", "armorBreak": "Skill", "canHitSameTarget": 1,
      "selfActionChange": { "changeType": 1, "param": "skill2_1_hit", "priority": 50, "keepFrame": true } }
  ]
},
{
  "id": "skill2_1_hit", "animKey": "Skill_B_1", "catalog": "Skill", "priority": 20,
  "autoNextActionId": "skill2_land_hit",
  "onLand": { "changeType": 1, "param": "skill2_land_hit", "priority": 100 },
  "armorPhase": [ { "range": { "x": 0, "y": 28 }, "level": "Skill" } ]
},
{ "id": "skill2_land", "animKey": "Skill_B_land", "catalog": "Skill", "priority": 20, "autoNextActionId": "idle" },
{
  "id": "skill2_land_hit", "animKey": "Skill_B_land", "catalog": "Skill", "priority": 20,
  "autoNextActionId": "skill2_2",
  "armorPhase": [ { "range": { "x": 0, "y": 9 }, "level": "Skill" } ]
}

关键点逐条看

  1. keepFrame: true：切到 skill2_1_hit 时接着当前帧播（同一个动画 Skill_B_1），玩家看不出切换。同时保留水平惯性，第 9 帧设置的 velocityX: 8 不会被清掉，角色继续往前飞。
  2. 命中版不配 attackPhase：已经打中了，不需要再打。也不配 events：从第 19 帧之后接着播，第 4 帧的生成事件本来就不会重放。
  3. 命中版要把霸体抄过去：变体是独立动作，armorPhase 不会继承。漏抄的话，命中后的下落过程会变成可被打断。
  4. onLand 与 autoNextActionId 都写：先落地就由 onLand 切走（优先级 100+20）；如果动画先播完而角色还在空中，autoNext 会切到落地动作，避免停在最后一帧的空中姿势。
  5. 空中动作兜底：skill2_1_hit 配了 onLand 而自己没有起跳段，框架把它当成"空中动作"。如果命中那一刻角色恰好已经在地面上，进入后会立即视为落地，直接走 skill2_land_hit，不会卡在空中姿势。

最后在 skills.json 里把整条链登记进同一段，CD 才会在 skill2_2 结束后开始：

{ "actionId": "skill2_1", "followActions": ["skill2_1_hit", "skill2_land", "skill2_land_hit", "skill2_2"] }
代价与取舍每个"命中才接"的分支要多配 1~2 个变体动作，改霸体、位移时要两边一起改。好处是每条路径都是显式的动作链，编辑器和自动校验都能看见，不存在隐藏状态。

ActionCommand · 指令

actions.json › ActionData › commands[]

一条输入条件。同一条里的所有按键都要满足；commands 里任意一条满足即可。

字段类型默认说明
pressstring[][]每个键都在缓冲时间内按下过（上升沿），且这次按下还没被用掉。多个键时顺序不限。
holdstring[][]每个键当前正按着。摇杆方向键只能写在这里。
releasestring[][]每个键在缓冲时间内松开过。用于蓄力释放。
validInSec字符串秒数0.2 秒（6 帧）press 与 release 的缓冲时间。写 0、负数、留空都按 0.2 秒。

按下与松开的消费规则

  • 按下：任何一次动作切换都会把所有未用的按下标记为已用。所以一次点击只能触发一次切换。
  • 松开：跨动作保留，只有再次按下同一个键才会作废之前的松开。所以"按住蓄力 → 进入蓄力动作 → 松开释放"可以跨动作成立。
  • 缓冲包含两端：第 F 帧的按下在 F ~ F+6 帧都算数（共 7 帧）。

示例

{ "press": ["Attack"], "validInSec": "0.2" }                    // 点一下（带预输入）
{ "hold": ["Attack"] }                                          // 按住
{ "hold": ["Down"], "press": ["Attack"], "validInSec": "0.2" }  // 下 + 攻击
{ "press": ["Skill1", "Attack"], "validInSec": "0.1" }          // 两键同按
{ "release": ["Skill1"], "validInSec": "0.2" }                  // 松开技能 1
{ "press": ["Skill2"], "release": ["Skill2"], "validInSec": "0.2" } // 0.2 秒内按下并松开 = 点按

Attack · 攻击数值

actions.json › ActionData › attacks[]

一段攻击命中后发生什么。按下面的顺序决定受击反应，命中一个分支就不再看后面的：

  1. 目标正被抓 → 只扣血
  2. 攻击的 armorBreak 低于目标霸体 → 只扣血（被挡住）
  3. 配了 grab → 抓取
  4. 目标在空中 → 按 air 重新击飞
  5. 配了 launch → 击飞
  6. 目标倒地 → 只扣血（需要 canHitLying 才能打到）
  7. 其余 → 僵直 hitStun + 击退 push

attack逻辑

伤害值（字符串）。每次命中都扣，包括被霸体挡住、目标被抓时。角色默认血量 1000。≤ 0 不扣血。

"attack": "50"

hitStun逻辑

地面僵直秒数。只在第 7 个分支生效。> 0 时目标进入僵直（循环播放 hurt_1 或 hurtAction），倒数结束回到 idle。新的僵直会覆盖剩余时间。为 0 且没配 hurtAction 时目标不僵直、不换动作，但击退仍然生效。

"hitStun": "0.6"   // 18 帧

push · 击退

字段类型默认说明
x字符串单位0沿攻击方面朝方向的总位移。
y字符串单位0纵深总位移。
inSec字符串秒数0在多少秒内完成。为 0 时没有击退。
tweenMethodstringLinearLinear 匀速，Slowly 先快后慢。区分大小写，写错按 Linear。
"push": { "x": "0.6", "inSec": "0.15", "tweenMethod": "Slowly" }

击退期间目标的摇杆移动和 rootMotion 都暂停。新的击退覆盖旧的。

launch / air · 击飞

字段类型默认说明
z字符串，单位/秒0竖直初速度，向上为正。
x字符串，单位/秒0沿攻击方面朝方向的水平惯性速度。
y字符串，单位/秒0纵深惯性速度。
  • launch：目标在地面（或倒地且 canHitLying）时把它打上天，进入 hurt_toair（或 hurtAction）。
  • air：目标已经在空中时使用，任何攻击都会按它重新击飞，动作固定为 hurt_inair。没配时使用全局默认 z=5、x=1。
  • 是否启用：z、x、y 任意一个写了就算启用，哪怕写的是 "0"。
  • 击飞期间重力 ×0.7（默认重力 30）；触地时 落地速度 × 0.5 ≥ 3 会弹起，否则倒地。
"launch": { "z": "11", "x": "3" },
"air":    { "z": "10", "x": "3" }
浮空连击的关键是 air只配 launch 的招式打空中目标时，会用全局默认的 z=5 把对手托起，往往不是你想要的高度。连段里每一招都应该写自己的 air。

armorBreak

破霸等级，取值同 ArmorLevel。攻击 armorBreak ≥ 目标当前霸体 才能造成完整受击反应。Invincible 霸体的目标完全打不到。

"armorBreak": "Skill"

canHitLying

bool，默认 false。能否打到倒地的目标（扫地）。打到时：配了 launch 会把对手重新挑起，否则只扣血。

RootMotionSegment · 位移段

actions.json › ActionData › rootMotion[]
字段类型默认说明
frameRangeFrameRange{0,0}生效区间。

战斗界面创建时预加载，找不到会报错。Unity 环境测试也会检查所有非空图标地址。

skills.json › data[]

cooldown逻辑

完整 CD 秒数。

类型字符串秒数
默认0

CD 什么时候开始

  • 放完最后一段：离开本技能所有动作（入口 + followActions）的那一帧开始，完整 CD。
  • 多段技能某段之后超时没接下一段：开始 CD，并返还该段的 cdReturn。
  • 释放过程中被打断（进入受击）也算离开。
"cooldown": "3"    // 90 帧
离开技能的 tick 记为 N，cooldown = "1"（30 帧） tick N : CD = 30 tick N+1 : CD = 29 ... tick N+30: CD 先归零，再判断输入 → 这一帧就能再次释放
skills.json › data[]

chakraCost逻辑

释放第一段时消耗的查克拉。不足时无法释放。

类型int
默认0

只检查、只扣第一段，后续段不消耗。实际扣除发生在真正进入入口动作时。因为开局查克拉为 0，消耗大于 0 的技能（奥义）要先攒查克拉。

"chakraCost": 2
skills.json › data[]

requireHurt逻辑

只能在受击中释放（僵直 / 击飞 / 被抓 / 倒地）。起身阶段不算。

类型bool
默认false
{ "id": "substitution", "button": "Substitution", "cooldown": "3", "requireHurt": true,
  "stages": [ { "actionId": "substitution" } ] }
入口动作必须配 breakHurt受击中普通取消检测是关闭的，只有 "breakHurt": true 的动作会被检查。requireHurt 而入口动作没有 breakHurt，技能永远放不出来，且没有任何报错。
skills.json › data[]

stages必填逻辑

技能段，按顺序为第 1 段、第 2 段……至少一段。

类型SkillStage[]
默认[]：技能永远放不出

多段技能怎么工作

stages = [multi_1 (stageDuration 2, cdReturn 4), multi_2 (stageDuration 1.5, cdReturn 2), multi_3] cooldown 12 按键 → multi_1 → 放完回 idle → 2 秒内再按 → multi_2 → 放完 → 1.5 秒内再按 → multi_3 → 放完 → CD 12 秒 └ 2 秒没按 → CD = 12 - 4 = 8 秒，回到第 1 段 └ 1.5 秒没按 → CD = 12 - 2 = 10 秒

同一时刻只有"下一段"的入口能进，其他段的入口被准入拦截，所以各段入口可以绑同一个按键。

一个动作只能属于一个技能段同一个动作 id 出现在两个段（或两个技能）里会报错，并且只有第一次登记生效。
skills.json › data[] › stages[]

actionId必填

本段的入口动作 id。由输入发起，受准入裁决（CD、段号、查克拉、受击条件）。

{ "actionId": "skill1" }

入口动作本身要在 actions.json 里配好 cancelTag（通常是 skill）和 commands，并且要有窗口放行这个标签（idle、move、普攻后摇等）。

skills.json › data[] › stages[]

followActions逻辑

本段的后续动作：落地、命中派生、收招、技能派生。处于这些动作期间仍算"正在释放本段"。

类型string[]
默认[]

为什么必须列全

  • CD：进入一个没登记的动作，技能就被认为"放完了"，CD 提前开始。
  • 查克拉：登记的动作（及其生成物）命中才算本技能的命中，会给查克拉。
  • 不受准入：后续动作不检查 CD 和段号。
{ "actionId": "skill2_1", "followActions": ["skill2_1_hit", "skill2_land", "skill2_land_hit", "skill2_2"] }
怎么找全从入口动作出发，沿着 autoNextActionId、onLand.param、selfActionChange.param、以及只在技能窗口里放行的派生动作，一直走到回 idle 为止，路上所有动作都要列进来。
skills.json › data[] › stages[]

stageDuration

本段放完后，接下一段的时限（秒）。最后一段无效。

类型字符串秒数
默认0：放完立即开始 CD

时限从离开本段时开始倒数，释放期间不倒数。设 W 帧时限、在第 N 帧离开：第 N+1 ~ N+W-1 帧按键能接下一段，第 N+W 帧超时。

时限内按钮会显示下一段的图标（没配就显示段号）。

"stageDuration": "2"
skills.json › data[] › stages[]

cdReturn

连段在本段之后中断时返还的 CD 秒数。

类型字符串秒数
默认0
"cdReturn": "4"   // cooldown 12 → 只放第 1 段时实际 CD 8 秒

实际 CD = max(0, cooldown − cdReturn)。最后一段的 cdReturn 不会被使用。

skills.json › data[] › stages[]

icon表现

轮到本段时按钮显示的图标，格式同技能 icon。留空用技能图标，并在按钮中央显示段号。

{ "actionId": "multi_2", "icon": "UI/SkillButton/xxx#xxx_1", "stageDuration": "1.5" }

查克拉规则

  • 开局为 0，上限 chakraMax。
  • 获得：某技能的任意段、后续动作或它生成的生成物命中时 +1。被霸体挡住、命中被抓目标也算。
  • 每轮一次：获得一次后，要等该技能 CD 结束（刷新）才能再获得。所以一个技能多段命中只给 1 颗。
  • 普攻等不属于任何技能的动作，命中不给查克拉。
  • 消耗：见 chakraCost。

spawns.json · SpawnDataContainer

生成物：投射物（Simple）和分身/召唤物（Actor）。生成物复用角色的整套动作系统，动作库与主人共用，它的动作就写在主人的 actions.json 里。

{ "data": [
  { "id": "naruto_skill2_fx", "type": "Simple", "initialActionId": "skill2_fx", "lifeTime": "3", "prewarm": 2 }
] }

生成流程

  1. 主人的动作在某帧触发 {"type": "Spawn", "spawnId": "…"} 事件。
  2. 记录生成请求：位置 = 主人该帧的 anchor + offset（留空为脚底），朝向与阵营继承主人，"来源技能"记为主人当前所在的技能。
  3. 本帧末尾（第 7 步）从实例池取出实例，进入 initialActionId，血量重置。下一 tick 才开始行动。
  4. 生成物命中的伤害、跳字归属主人；按来源技能给主人加查克拉。
不能配置的属性阵营、朝向、位置都由触发事件决定；能否被打由 type 决定。spawns.json 里没有这些字段。

类型string

spawns.json › data[]

brain / script

Actor 的输入来源。None：不注入输入，只走动作链；Script：按脚本在指定帧"按键"。Simple 忽略这两个字段。

script[] 字段类型默认说明

  { "frame": 40, "hold": 1,  "buttons": ["Skill1"] }
]

上例：第 2 帧普攻，第 12 帧再按一次接连段，第 30~39 帧向前走，第 40 帧放技能 1。

附录 A · 帧判定口径对照

同样写 {x: 2, y: 3}，不同字段判断的"帧"略有不同。大多数情况下不用关心，调试"差一帧"的问题时查这张表。

字段判断哪一帧备注
beCancelledTag、attackPhase（是否开启）、inputAcceptance本 tick 处理的帧动画停在末帧时按末帧
attackPhase（逐帧检测）本 tick 实际处理的每一帧停在末帧时不再检测，打不到人
armorPhase刚处理完的帧
defensePhase即将显示的帧比上面早一帧
rootMotion按区间进度分配每处理一帧拿走 1/区间长度
events本 tick 处理的帧只触发一次；中途进入不补发
velocityZ、velocityX/Y区间起点 x 那一帧区间终点无意义
